# ClipFender — Stage 10 Changes

Дата: 2026-09-26

## 1. Что добавлено в Idea Mode

### Жанр
В активную страницу `/search` добавлено отдельное поле `Жанр` (`select`), независимое от `Настроение`.

Доступные варианты:
- Экшн
- Драма
- Романтика
- Хоррор / трагедия
- Комедия
- Приключения

Backend принимает необязательный query-параметр `genre` и валидирует его без изменения старого контракта `/api/edit-idea`.

### Персонаж
Добавлено отдельное поле `Персонаж` с `datalist` на основе текущего набора персонажей ClipFender:
- Джон Сноу
- Джейми Ланнистер
- Дейенерис Таргариен
- Тирион Ланнистер
- Арья Старк
- Серсея Ланнистер

Имя персонажа передаётся в `/api/edit-idea` отдельным необязательным параметром `character` и не смешивается с общим `query`.

### Ranking и `why`
`genre` и `character` участвуют в отдельном relevance-слое поверх существующего Edit Suitability/scoring.

В объяснение карточек добавлены причины вида:
> «выбрано под жанр «экшн» и персонажа «Джон Сноу»»

Существующие причины по Edit Suitability, action/cinematic/clean, фильму, настроению и темпу сохранены.

## 2. Исправление пустого кэша в `/api/edit-idea`

Ранее Idea Mode использовал только локальный пул и при его отсутствии возвращал `no_material` с требованием сначала выполнить обычный поиск.

Теперь порядок такой:

1. Ищется релевантный материал в существующем общем cache.
2. Проверяется недавний DB-пул только на фактическую релевантность перед использованием.
3. Если релевантного материала нет, автоматически вызывается существующий `backend.services.youtube.search_youtube()` через общий цикл:
   `quota → search_youtube → remove_duplicates / soft_edit_pool → scoring → save_videos / save_search_state`.
4. Результат сохраняется в тот же общий `clipfinder_shared:<normalized-query>` cache.
5. После этого из полученных реальных материалов строится `INTRO → BUILD-UP → CLIMAX → OUTRO`.

Для live fallback используется один сценарный поисковый запрос, сформированный из `character + film + query + genre`.

Важно: публичные `/api/search`, `/api/edit-idea` и `/api/load-more` не удалялись и не переименовывались; новые параметры `genre` и `character` являются необязательными.

## 3. Новая цепочка «Сценарий → реальные материалы»

Сценарий больше не заканчивается после генерации структуры.

После выбора параметров пользователь получает строку `АВТОПОИСК` с фактическим поисковым запросом, а backend автоматически подтягивает реальные YouTube-материалы при отсутствии релевантного кэша.

Это реализует подтверждённую в Stage 10 идею: пользователь задаёт сценарий по фильму/сериалу, а ClipFender сам ищет материал, соответствующий этому сценарию, без обязательного предварительного обычного поиска.

## 4. Раскадровка

Idea Mode теперь отображает результат как storyboard:
- этапы `INTRO / BUILD-UP / CLIMAX / OUTRO`;
- номера этапов;
- номера отдельных shots;
- более крупные preview;
- отдельный `search focus` для каждого этапа;
- визуальный connector/стрелка между этапами;
- более заметные hover-состояния карточек;
- профиль сценария: персонаж, фильм/сериал, жанр, настроение, темп;
- строка `АВТОПОИСК`.

Добавлена кнопка `↓ СКАЧАТЬ РАСКАДРОВКУ`.

Экспорт реализован без новых тяжёлых зависимостей: `window.print()` + специализированный `@media print`.

## 6. Небольшие отличительные функции

### Реализовано
1. **«✦ СЛУЧАЙНАЯ ИДЕЯ»** — случайно выбирает реального персонажа из текущего набора, жанр, настроение и темп и запускает обычный Idea Mode с реальным backend.
2. **«Сценарий → автоматический поиск материалов»** — реализовано как часть основного Stage 10 flow через общий live-search/cache механизм.

### Предложено, но не внедрено
3. **«Следующий шаг»** после сценария — быстрые действия для повторного поиска/изменения параметров.
4. **«Повторить с изменением»** — быстрые варианты темпа/атмосферы для повторного сценария.

Эти два пункта оставлены вне реализации Stage 10, чтобы не расширять публичный API и UI без отдельного подтверждения.

### Ограничение браузерной проверки
В рабочем окружении headless Chromium запрещает прямую навигацию на loopback/test origins (`ERR_BLOCKED_BY_ADMINISTRATOR`). Поэтому UI smoke-test выполнялся на реальном server-rendered `/search` markup, загруженном в DOM harness, с production `stage8-idea.js`, а API-вызовы `/api/search` и `/api/edit-idea` подменялись детерминированными ответами, чтобы не расходовать YouTube quota.

Отдельно реальные HTTP routes сервера проверены через `GET /archive`.

Браузерный smoke-test завершился без `pageerror` и без console errors.

## 9. Расхождение между описанием Stage 9 и исходным ZIP

В исходном ZIP уже присутствовал файл `CHANGES_STAGE10.md` и несколько Stage 10-related файлов/архивов, однако активная реализация `/search` оставалась на `stage8-idea.js` / `stage8-idea.css`, а активный `backend/api/edit_idea.py` не имел `genre` / `character` и не выполнял live fallback при пустом релевантном кэше.

В Stage 10 ориентиром был активный код проекта из ZIP; существовавшие ранее Stage 10-related архивы не использовались как замена активной реализации.
